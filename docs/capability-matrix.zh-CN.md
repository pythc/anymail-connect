## 功能对齐规则

官方基线来自本次会话实际可发现的工具名称与描述，未访问邮箱、未执行工具。标记“观察到”只说明工具被提供，不说明账号已授予对应权限、执行可靠或其他客户端也提供该工具。

| 用户能力 | Gmail 工具元数据 | Outlook 工具元数据 | 通用底座实现策略 | 验收阶段 |
| --- | --- | --- | --- | --- |
| 账号身份与多账号 | 观察到 profile | 观察到 profile | MCP profile 标识连接身份；每次调用再验证 account ACL | P0/P1 |
| 最近、未读、条件搜索 | 观察到搜索/标签计数 | 观察到列表/搜索 | 统一结构化条件；原生搜索语法用显式扩展，不冒充跨服务商兼容 | P1 |
| 单封/批量正文 | 观察到 | 观察到 | 有限批次，逐项保留成功/失败；读取默认不改已读 | P1 |
| 会话与线程 | 观察到单线程/批线程 | 消息工具可见；专用完整会话工具未观察到 | 原生 thread/conversation 优先；IMAP 用 References/In-Reply-To 推断并标注 | P1/P2 |
| 附件列举与下载 | 观察到读取与提取 | 观察到列举/下载 | 元数据先行；鉴权文件资源，按需解析；保留截断/不支持状态 | P1 |
| 附件上传和写信 | MIME 写信入口可见 | 观察到文件引用附件接口 | 先取得受保护上传句柄，再绑定草稿；宿主上传能力单独验证 | P1/P3 |
| 草稿创建/编辑/列表 | 观察到 | 创建可见，通用修改/列表入口未观察到 | 服务商草稿优先；不支持安全更新则明确为应用内草稿 | P1 |
| 发送新信/草稿 | 观察到 | 观察到 | 发送意图、可信用户授权、操作台账与不确定状态处理 | P1 |
| 回复/全部回复/转发 | 观察到转发及线程相关能力；独立 reply 工具未观察到 | 观察到直接操作与草稿 | 正确引用原邮件，过滤本人地址，保留收件人预览与附件选择 | P1 |
| 已读/未读/星标 | 标签/批处理入口可见 | 已读修改可见 | IMAP flags / Gmail labels / Graph 字段映射；逐账号能力探测 | P1/P2 |
| 归档、移动、垃圾箱 | 归档/删除入口可见 | 移动入口可见；独立删除工具未观察到 | 保留原生语义；默认可恢复移入垃圾箱，不暴露通用永久删除 | P1/P2 |
| 标签/分类/文件夹 | 标签查询/创建/应用可见 | 分类与文件夹入口可见 | 三种独立对象，不能把全部 Gmail 标签压成文件夹 | P2 |
| 批量搜索后整理 | 观察到 | 批量读取可见，通用批量写未观察到 | 冻结目标集合、预览影响数、逐项结果与取消/限额 | P2 |
| 定时发送 | 未观察到专用工具 | 观察到 | 后台持久队列；发送前重检权限；与服务商原生计划分开标记 | P2 |
| 联系人/联系人文件夹 | 未观察到 | 观察到查询及 CRUD | Graph 扩展；Google People/CardDAV 后续；仅邮件往来推断不能冒充通讯录 | P2/P4 |
| 退订 | 未观察到专用工具 | 退订头及 mailto 发送可见 | 先展示目标；mailto 视为发送，HTTP 退订单独能力与权限 | P2 |
| 共享/委派邮箱 | 未证明 | 部分工具描述提到共享路由，完整集未发现 | 先支持明确授权的 Graph 共享账号，不将普通账号登录当作委派授权 | P4 |
| 引用/预览/文件展示 | 元数据不能证明全部 UI | 同左 | 自有绝对来源 URL + 可选 MCP Apps；避免依赖宿主私有文件协议 | P0/P3 |
| Company knowledge / 深度检索 | 本次未验证 | 本次未验证 | 标准 search/fetch 作为兼容入口；后台索引与宿主资格分别验证 | P3 |

未观察到某工具不等于产品永远不支持该功能；官方插件、底层服务商 API 和本项目目标是三个不同集合。

## 服务商适配与限制

下表“路径有资料”不等于本项目已通过该邮箱测试。自定义域名也不能只按邮箱后缀判断后端。

| 服务商/部署 | 目标路径 | 当前资料判断 | 需要实测/不能默认的内容 |
| --- | --- | --- | --- |
| Gmail 个人 | Gmail API / OAuth | 路径有官方资料 | 公共 OAuth 审核、标签、会话、草稿、搜索、撤权 |
| Google Workspace | 同上，用户委派优先 | 路径有官方资料 | 管理员限制；不默认使用全域委派 |
| Outlook.com / Hotmail | Graph / 委派 OAuth | 路径有官方资料 | 个人账号权限、搜索和附件行为 |
| Microsoft 365 / Exchange Online | Graph / 委派 OAuth | 路径有官方资料 | 租户同意、条件访问、共享/Send As 等权限 |
| QQ / Foxmail 品牌地址 | IMAP/SMTP + 授权码 | QQ 路径有连接器资料；Foxmail 品牌地址尚待逐账号核实 | SMTP/IMAP 主机与认证名、中文、发件箱副本、登录风控 |
| 163 / 126 / yeah | IMAP/SMTP + 授权码 | 网易授权机制有官方资料 | 各品牌账号和套餐、服务器设置、IMAP ID、草稿/特殊文件夹 |
| iCloud / 自定义域 iCloud | IMAP/SMTP + 应用专用密码 | Apple 官方资料 | 认证名差异、别名发件权限、特殊文件夹 |
| 企业微信/腾讯企业邮箱 | 企业协议或专用 API | 作为候选，尚未取得完整官方能力正文 | 管理员客户端开关、协议权限、授权码/密码规则、共享邮箱 |
| 网易企业邮、阿里企业邮等 | 企业协议或专用 API | 候选，不宣称品牌支持已认证 | 套餐/地区/管理员设置/固定出口 IP |
| 自建 Dovecot 类 IMAP | IMAP/SMTP + 管理员配置认证 | 协议路径可行 | 扩展能力、证书链、网络、配额和并发限制 |
| Fastmail 等 JMAP 服务 | JMAP，IMAP 可作为备选 | 标准已读取，品牌接入文档未完整验证 | JMAP 开放条件、token/OAuth、限流和推送 |
| Proton Mail | 本地 Bridge + IMAP/SMTP | 官方明确提供付费桌面桥接 | Bridge 常驻、连接边界、解密数据外发与跨端限制 |
| 本地 Exchange Server | 管理员开放的 IMAP/SMTP；必要时 EWS 扩展 | 不等同于微软云 | 网络与身份、实际服务版本，单独合同/项目验收 |
| POP3-only、Web-only、禁用第三方访问 | 不作为通用写回支持 | 无完整通用路径 | 只读导入若有需求再评估；不采用网页爬取绕过登录策略 |

资料入口见[来源表](sources.md)；所有服务商应建立 `documented → implemented → lab-tested → real-account-tested` 状态，不把四者合并。

## 能力协议建议

`accounts.get_capabilities` 返回：

- 每项能力的状态：`native`、`emulated`、`unsupported`、`unknown`。
- 当前连接的授权范围、只读策略、限制原因、附件上限、需要重新授权的能力。
- 搜索方式和覆盖范围、线程来源、草稿保存位置、发送副本行为。
- `last_checked_at` 与测试证据版本；发现或授权变更时重新计算。

能力和授权分开：后端支持某 API 不等于该用户有权调用。`tools/list` 可以减少无权限工具的暴露，但每个实际调用仍须强制鉴权。不支持的操作返回明确错误，不能静默降级为另一种语义。
