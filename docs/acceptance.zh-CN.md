## 1. 证据记录

每份验收记录包含：commit、工具 schema 版本、部署版本、服务商、账号类型/套餐、MCP 客户端及版本、授予权限、测试时间/时区、用例 ID、预期/实际、操作 ID、脱敏服务商回执、已知缺口。

密码、token、授权码、真实私人邮件和可下载私人附件的 URL 不进入公开仓库。公开记录使用受控夹具和脱敏账号；私有原始回执保存在部署方受限位置。

状态分为 `not_run`、`pass`、`fail`、`blocked`，blocked 写明外部原因；未测试不能标记通过。独立记录单元/协议实验室/真账号/ChatGPT 端到端结果。

## 2. 真实账号基础闭环

对声明支持的每个“服务商 × 账号类型”执行：

1. 新连接、失效凭证、重新授权、撤权；确认模型和日志没有凭证。
2. 读取最近/未读邮件不改变已读；分页、空页、最后一页、同时间戳、无权限和限流行为正确。
3. 中英文主题/地址/正文，GBK 等编码，multipart/alternative、内嵌图片、长引用、重复 Message-ID、缺头与损坏 MIME。
4. 搜索发件人、日期、主题、正文与附件条件；明确时区、包含边界、搜索范围和缓存覆盖，不把不支持的原生语法静默忽略。
5. 附件元数据、下载、上传与发信；多附件、同名文件、错误 MIME、超大文件、解析超时和压缩炸弹处理。
6. 创建与更新草稿，关闭本服务后在邮箱客户端确认保存位置；编辑冲突保留旧附件；应用内草稿明确标注。
7. 新信、回复、全部回复、转发；核对 From/Reply-To/To/Cc/Bcc、References、中文、别名、附件与本人地址过滤。
8. 受控发送核对服务商接受回执和测试收件箱的实际接收；记录二者不同，检查发件箱副本不会导致重复发送。
9. 标记已读/未读、移动、标签/分类/垃圾箱，刷新原邮箱客户端核对；先选错账号的拒绝测试再测成功路径。

## 3. 恢复与发送不确定性

| 故障 | 必须观察到的行为 |
| --- | --- |
| SMTP DATA 已接受但最终响应丢失 | 状态 unknown；不自动重发；可查询操作并提示对账 |
| 多收件人部分 RCPT 接受 | 分别记录收件人结果；不向全部收件人重放 |
| Graph 202 或 Gmail 发送已完成后 API 进程崩溃 | 保留操作记录；恢复时先对账，不能创建新发送意图 |
| 两个 worker 同时取同一发送任务 | 最多一个取得提交租约；租约失效后先判断是否已越过外部提交点 |
| 已发送但 APPEND 发件箱副本失败 | 显示副本失败；原信不重发 |
| 用户批准后修改 To/Bcc/正文/附件 | 旧授权不可用于新版本 |
| 账号在计划发送前撤权 | 停止任务；不凭缓存授权继续提交 |
| 取消与调度提交发生竞争 | 原子确认状态；已提交后不能谎报取消成功 |
| IMAP UIDVALIDITY 重置、文件夹重建/移动 | 旧引用失效；不能误读/误删另一封邮件 |
| Gmail history 404、Graph delta 失效、漏推/重复推 | 恢复同步且显式显示范围/新鲜度；不丢事件或重复对象 |
| 429 / Retry-After / 短时断网 | 有限重试与退避；读/同步可恢复，未知发送不自动重试 |

## 4. 身份与安全

- 两个租户和两个用户互换 account/message/attachment/draft/operation ID，必须拒绝；缓存、队列、文件资源和 UI 链接也执行同样检查。
- 错误 issuer/audience、过期 token、撤权、PKCE 校验失败、redirect 篡改、OAuth state 重放均拒绝。
- 检查外部账号授权与 MCP 客户端同意独立；拒绝把第三方 access token 直接作为 AnyMail token。
- 恶意邮件正文要求转发到攻击者地址、外传附件或读取凭证，不得生成发送授权。MCP 工具注解只辅助宿主，不代替后端检查。
- 自定义邮件主机、OAuth metadata、Autodiscover 和 URL 重定向不能访问宿主元数据、loopback 或其他租户内网；管理员内网例外只能命中精确配置。
- HTML 脚本、远程图片、SVG/附件主动内容、链接、异常 MIME 不导致执行或无授权外连。
- 服务端授权记录只能来自可信认证 UI 或有等价可验证证明的宿主；模型调用“准备/确认”不构成用户点击。
- 日志、错误、崩溃转储和公开诊断包不含密码、token、正文或附件内容；测量删除任务对在线数据、缓存和备份的不同覆盖。

## 5. ChatGPT 端到端

对目标账号、工作区和声明支持的 web/desktop/mobile 分别检查，不把 Codex CLI 成功外推 ChatGPT 成功。

- 自定义 MCP 发现、OAuth、profile 多账号、撤权/重连和工具元数据刷新。
- 自然语言“查过去一周的发票”“阅读这一组往来”“回复全部并带上附件”等任务的工具选择、参数与来源引用。
- 邮件预览、附件显示/下载/上传、草稿编辑和实际发送确认；不支持 UI 的宿主仍可完成声明的纯工具任务。
- 账户切换与跨账号搜索的部分失败；错误时不展示另一账号的缓存。
- 超长正文与附件提取的截断提示和完整内容获取；引用链接需要当前用户权限，不能泄漏到公众。
- `search` / `fetch` schema 与只读标注通过检查；Company knowledge/检索入口资格与真实效果另记，不因 schema 合格标记“已同步”。

插件审核提交、审核通过、公开发布分别记录，不互相替代。

## 6. 升级、回滚与运维

从含草稿、同步游标、已提交/未知发送和定时任务的数据库升级，再回滚兼容版本。确认备份可恢复、队列不重放、旧授权不会绕过新策略、稳定消息链接可用。迁移中途失败必须可恢复或明确阻止启动。

对约定邮箱数、邮件量和附件分布测量初始化时间、增量延迟、P50/P95 读取延迟、连接数、内存、索引和存储；指标目标在 P0 根据真实样本冻结，不预先虚构吞吐承诺。

对外发布至少要求：核心功能闭环通过；跨租户与发送不确定性等关键用例无未解决失败；声明支持范围的真实账号与目标客户端证据齐全；已知限制和运维恢复文档公开。
