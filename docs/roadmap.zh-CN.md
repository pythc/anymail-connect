# 实施路线、投入与决策门槛

> 历史调研/设计文档。当前代码与验证进展见 [实现状态](implementation.zh-CN.md) 和 [TODO](../TODO.md)；文中的“未开始”描述保留的是立项时状态。

日期：2026-11-04。以下是工程估算与建议，不是报价或交付承诺。用户范围已明确：个人与企业都覆盖，先做统一底座。

## 1. 推荐范围

第一轮真实账号矩阵：QQ、163、iCloud、Gmail 个人、Outlook 个人、Microsoft 365 测试租户、一套标准企业 IMAP。Workspace、腾讯/网易等企业品牌、共享邮箱各自增加测试账号，不从通用协议测试外推品牌认证。

自托管优先，底座从第一天建模租户与主体；多租户托管在隔离与运维验收前不公开。账号、凭证和测试邮件均由参与者按需授权，不读取生产私人邮件作为默认测试材料。

## 2. 阶段和交付门槛

工期假设：两名熟悉后端/OAuth 与全栈集成的工程师持续参与，安全/运维按需支持，测试邮箱与目标 ChatGPT 使用权限及时到位。区间是累计研发时间，不包含不可控的外部审核等待。

| 阶段 | 累计时间估算 | 必须交付 | 退出条件 |
| --- | --- | --- | --- |
| P0 可行性验证 | 1–2 周 | 固定基线、账号与权限模型、MCP/OAuth 技术验证、三条后端的最小受控闭环 | 在目标 ChatGPT 账号完成自定义连接、鉴权、搜索/阅读；确认附件/上传/确认机制；确认三条后端可达 |
| P1 核心 Alpha | 4–6 周 | 多账号、能力声明、搜索/正文/附件、草稿、回复/转发、发送台账、已读/移动 | 受支持测试账号完成邮件闭环；跨租户拒绝；unknown 发送不重发；基本断线恢复 |
| P2 可靠性与扩展 | 7–10 周 | 增量同步/重同步、批量整理、分类/标签、定时发送、Graph 联系人、撤权和审计 | 真账号回归、失败注入、权限撤销、中文/复杂 MIME、计划任务取消通过 |
| P3 ChatGPT 产品体验 | 9–14 周 | 可选邮件/草稿 UI、文件交付、来源引用、search/fetch、插件包装和评估材料 | 目标客户端实测；声明支持范围；提交材料完整，不把提交等同审核通过 |
| P4 企业适配 | 12–20 周 | 共享/委派、企业身份/内网策略、更多品牌、部署与回滚演练、需要时 CardDAV/JMAP | 指定企业环境与账号分别验收；值班诊断与恢复证据齐全 |

可用 Beta 的规划窗口约 **8–12 周**，允许将 P3 中最必要体验提前，其余增强后排。针对明确服务商矩阵的企业增强版本约 **12–20 周或更久**。只有一人兼职、没有真邮箱、或“所有企业环境都要第一版支持”时，上述估算不成立。

前两周不应只做一个漂亮的 `tools/list` demo。要至少验证一条复杂 MIME、一次真实草稿写回、一次受控发送、一次撤权和一次发送确认丢失的处理路径。模拟器结果与真实邮箱结果分别记录。

## 3. 必须单列的外部依赖

- Google OAuth：最小权限申请；涉及 restricted scopes 和服务端处理时，准备验证/安全评估路径。内部用途或其他适用例外需要按实际应用类型核实，不把测试账号运行成功当作公开发布许可。[官方 scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)
- Microsoft：个人账号与工作/学校账号的应用注册、租户同意、共享邮箱与发件权限；企业的条件访问和网络限制需要管理员参与。
- OpenAI：自定义连接入口受账号与工作区策略影响；公开目录需稳定端点、域名验证、测试账号和审核材料，完成研发不等于获准发布。[提交要求](https://developers.openai.com/plugins/deploy/submission)
- 账号与网络：标准协议开关、授权码、固定出口 IP、端口出站限制、内网代理和证书。邮箱域名或 MX 不是自动配置的充分证据。
- 企业数据治理：凭证托管、邮件/附件缓存、发送至模型的数据范围、保留和删除。具体法律/合规结论本次未作法律审查，正式托管前按服务地区与客户要求评估。

## 4. 成本模型

研发主成本按人周估：两人 8–12 周约 16–24 人周，企业增强阶段两人 12–20 周约 24–40 人周；这是累计投入的估算区间，不应相加。预算可用“人周 × 团队实际全成本”换算，外部测评/设计/运维另列。

运行成本至少包括：API/worker、数据库、存储与备份、队列、IMAP 长连接、全文索引、附件解析、出口流量、监控与值班、第三方审核或授权。未进行压测和云资源询价，因此不报伪精确月费。

一个**仅用于容量演算**的例子：100 用户 × 2 邮箱 × 每箱 5,000 封 = 1,000,000 封。若每封元数据平均 3 KiB，纯载荷约 2.86 GiB；若正文平均 50 KiB，正文另约 47.7 GiB。实际还要加行/索引开销、附件、复制、备份和保留期；这些平均值是假设，必须用受控样本测量。仅 200 个账号并不意味着只需 200 条连接，因为文件夹监测和服务商策略会影响连接数。

可减少首期成本：按需拉取正文与附件，限定同步时间窗口，优先服务商搜索，不默认整库 embedding，不默认持久化附件，不提前搭建大规模集群。

采购对照：EmailEngine 当前软件年费见[调研报告](research.zh-CN.md)；Nylas 按实际商用方案和数据处理条件询价。没有采购任何服务或启动付费试用。

## 5. 项目组织建议

拟议目录（尚未创建实现目录）：

```text
apps/mcp-server/       # HTTP MCP 与业务工具
apps/connection-ui/    # 登录、邮箱连接、审阅与来源页面
apps/worker/           # 同步、队列、计划发送
packages/mail-domain/ # 统一模型、能力、错误与接口
packages/providers/   # Gmail / Graph / IMAP-SMTP / later JMAP
packages/testkit/     # 受控邮箱夹具、协议故障与一致性测试
deploy/               # 容器与运维配置
docs/                 # 当前调研与设计
```

实现代码前锁定：项目许可证、MCP/Node/库版本、实际测试账号矩阵、部署边界及数据保留默认值。无需在这些决定前批量接入用户真实邮箱。

## 6. Go / No-go

**继续自研**：P0 在目标 ChatGPT 账号可用；原生与标准协议闭环成立；团队愿意承担同步与权限维护；国内/企业实测和自托管构成清楚的差异化。

**转采购或缩小范围**：唯一需求是个人尽快收发；已有产品满足；无法取得目标客户端权限；关键邮箱禁止第三方接入；成本只够写 MCP schema 而无力维护长期服务。

**拒绝宣传的结论**：未测的品牌支持、所有邮箱 100% 覆盖、和官方插件所有体验完全一致、从 SMTP/HTTP 接受推断投递成功、从单账号测试推断多租户安全。

## 7. 当前完成状态

- 已完成：官方资料和现有产品调研、路线建议、功能矩阵、架构与验收设计、公开仓库初始化材料。
- 未开始：运行时代码、适配器、真实账号接入、服务部署、用户试点、性能测试、外部审核与目录发布。
- 仓库存在且公开，只能证明项目资料已发布，不能证明邮件能力已实现。
