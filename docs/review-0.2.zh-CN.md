| 冻结版本的问题 | 已观察到的证据与限制 | 修复与回归 |
| --- | --- | --- |
| IDLE 事件缺少待处理写入上限 | 200 个事件产生 200 次并发入队调用，最终只存一行；没有诱发或测量生产 OOM | 固定 500ms 合并窗、每账号一笔在途写入和一个后续信号；回归在首笔阻塞时再投递 200 个事件，最大并发为 1，后续信号保留 |
| IDLE 初始化完成前无法取消 | 实际 TLS greeting 后卡住 CAPABILITY，abort 后 250ms watch 和连接仍在；连接数上限与容器强制退出限制影响 | 取消覆盖 DNS/连接/认证，总初始化期限 15 秒；真实协议回归验证中途取消关闭、第二次 CAPABILITY 已到达且约 15 秒超时关闭 |
| 只读客户端可以修改推送配置 | 仅 `mail.read` 的真实 HTTP 请求启用/关闭均返回 200 并调用服务商；外部账号仍 404，无越租户或邮件修改 | 启停要求 `mail.write`，worker 续期具有相应权限；HTTP/直接服务方法均拒绝只读调用，状态仍可读，具备管理权限的所有者可配置 `writable=false` 邮箱 |

另修复一次暂时续期失败丢失旧订阅有效期的正确性问题：保留 enabled 旧记录的有效期、服务商 ID 和加密 clientState，Gmail/Graph 回归均验证失败后仍接收未过期合法回调。迁移命令输出也改为实际 schema v2。

正式扫描保留冻结版本的三个问题；之后的修复经过源码复核和回归，没有将旧扫描改写为“最终版本零问题”，也没有声称完成第二次完整扫描。专项复核未发现新的可证实缺陷，这不是无缺陷保证。
